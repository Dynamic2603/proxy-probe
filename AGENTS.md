# Рекомендации и контекст для агентов (AGENTS.md)

Код — документация: механика проверки описана в пакете `proxy_probe` (константы, классификатор, схемы конфигов движков, кэш).

---

## Внешние источники информации и движки

1. **Репозиторий Throne**: `https://github.com/throneproj/Throne` (C++/Qt, движки sing-box и Xray).
   - Каталог данных: `%LOCALAPPDATA%\Throne` или `%APPDATA%\Throne`.
   - `config\throne.db` — SQLite: активные группы, URL подписок, схемы `outbound_json`. Скрипт использует безопасный снимок БД с WAL в `%TEMP%\proxy-probe\snapshot\`.
   - `ThroneCore.exe` — определяет версии движков при запуске.
2. **Официальные релизы движков (GitHub Releases)**:
   - Актуальные версии определяются динамически из `ThroneCore.exe` (sing-box `https://github.com/SagerNet/sing-box/releases` и Xray `https://github.com/XTLS/Xray-core/releases`).
   - Бинарники кэшируются в папке `bin/` в корне проекта (или переопределяются через `PROXY_PROBE_BIN_DIR`) и валидируются по SHA-256 из релизов upstream (`.dgst` / `.sha256`).
3. **Целевой API и гео**:
   - `https://generativelanguage.googleapis.com/v1beta/...` — Gemini API (маркер гео-блока: `User location is not supported`).
   - `https://ipwho.is/` — гео-определение egress-IP для отчёта.
4. **Защита от исчерпания квот agy / Gemini**:
   - Автоматический выбор легковесной Flash-модели через `detect_best_agy_model` (приоритет: `flash.*low` -> `flash.*medium` -> `flash`; переопределение через `--agy-model` / `AGY_MODEL`).
   - Кэширование выбранной Flash-модели в метаданных `results.json` (`meta.best_model`, TTL 24ч) устраняет повторные вызовы `agy models` (9с) при регулярных запусках.
   - Семафор ограничения параллелизма к `agy` (`--agy-concurrency`, по умолчанию 2 процесса).
   - Автомат аварийного отключения `QuotaCircuitBreaker`: при ошибке `individual quota reached` вызовы `agy` мгновенно отключаются для последующих серверов, сохраняя только сетевой preflight/geo; статус `UNKNOWN` исключён из кэширования в `results.json`.
   - Предстартовая проверка `check_agy_health` предупреждает об исчерпании квоты до запуска тестирования пула.
5. **Дедупликация и кэширование по конфигурации (SSOT)**:
   - Канонический ключ `Server.config_identity` нормализует параметры между диалектами Xray и sing-box (`protocol:host:port:cred:sni:reality_pk:fingerprint:flow:alpn:path`).
   - Ленивая мемоизация SSOT-свойств (`config_identity`, `cache_key`, `sni`, `fingerprint`, `is_tcp_protocol`) на экземпляре `Server` устраняет десятки тысяч избыточных вычислений и ускоряет дедупликацию в 20 раз (0.02с на 14k серверов).
   - Идентичность устраняет зависимость от диалекта и исключает артефакты БД (например `packet_encoding: xudp`), позволяя свежим записям из онлайна (`fresh`) вытеснять устаревшие копии из локальной БД Throne (`db`).
   - Профили с различными uTLS фингерпринтами (`chrome`, `firefox`, ...) сохраняют независимость в кэше и пуле проверки.
6. **L4 TCP предфильтр (Stage 0)**:
   - Быстрый отсев недоступных хостов по сокетному 3-way handshake (`socket.create_connection`) перед запуском локальных движков `sing-box` / `Xray`.
   - SSOT дедупликация эндпоинтов `(server, server_port)`: уникальный хост проверяется строго один раз параллельно (`batch_probe_tcp`), результат проецируется на все профили этого эндпоинта.
   - Изоляция UDP-протоколов: `hysteria2`, `tuic`, `wireguard` прозрачно минуют предфильтр (`Server.is_tcp_protocol`).
   - CLI-флаги управления: `--no-tcp-prefilter`, `--tcp-timeout` (по умолчанию 1.5с), `--tcp-concurrency` (по умолчанию 200 воркеров).
7. **Оптимизация производительности проверки движками (Stage 1)**:
   - In-Memory запуск: передача конфигурации в `sing-box` (`-c stdin`) и `Xray` (`-c stdin:`) через `stdin`, сбор вывода через in-memory пайп. Файлы и каталоги на диске во время проверки не создаются.
   - Фильтрация по представителям эндпоинтов (Host-Representative First): первоочередная проверка по 1 представителю от каждого уникального сокета `(server, server_port)`. Падение туннеля представителя по сетевому таймауту мгновенно отсекает зависимые профили этого хоста (флаг отключения: `--no-rep-filter`).
   - Настройка сетевого конвейера: `--preflight-timeout` (по умолчанию 2.5с вместо 4.0с), адаптивный дефолт параллелизма `--jobs` (`min(32, max(8, cpu*2))`).
8. **Интеллектуальное именование и метаданные egress (SSOT)**:
   - 100% генерация собственного канонического имени (`Server.formatted_tag`): полный отказ от эвристик, разбора или угадывания паттернов в исходных названиях подписок. Имя формируется строго из объективных фактов.
   - Извлечение расширенных данных egress-геолокации (`ipwho.is`): `country_code`, `city`, `org`/`isp`, `flag`.
   - Автоматическое обогащение накопленного кэша `results.json` недостающими гео-полями по `ip_out` (`enrich_cached_ok_geo`).
   - Формирование канонического имени: `{flag} {code}, {city} | {org} (sni: {sni}, fp: {fp})`. При отсутствии гео детерминированный фоллбэк на `{server}:{server_port} (sni: {sni}, fp: {fp})`.
   - Экспорт в `proxy-ok.txt` с каноническим тегом для каждого проверенного узла.
9. **Сквозной порядок серверов как в UI Throne (SSOT)**:
   - Порядок вкладок подписок/групп: строго `groups_order.display_order` из `throne.db`.
   - Порядок профилей внутри каждой группы: строго `groups.profiles_json` из `throne.db` (порядок ручной сортировки / drag-and-drop в UI Throne).
   - Порядок онлайн-подписок: сохранение исходной последовательности ссылок в потоке подписки.
   - Сквозная нумерация `s.index = 1..N` фиксирует UI-порядок при первом сборе.
   - Очередь выполнения Stage 0 (L4 TCP) и Stage 1 (движки), терминальная таблица, итоговый отчёт `report.md` и экспорт `proxy-ok.txt` строго следуют UI-порядку `s.index` без пересортировки по статусам или ключам словаря.
10. **Скоринг надежности и удержание серверов (Grace Period & Lifecycle)**:
    - Разделение факта проверки (`ProbeResult`: `AGY-OK`, `DEAD`, `AGY-BLOCK`) и политики удержания (`LifecycleState`: `ACTIVE`, `DEGRADED`, `DEAD`).
    - Рейтинг надежности `score` (0..100): базовые 70 баллов при первом успехе, бонус до +20 за повторные успешные проверки, штраф за высокую задержку (>150мс) и штраф -30 за каждый сбой подряд.
    - Grace Period: при случайном сетевом сбое ранее проверенный узел не выкидывается из пула, а переводится в статус `DEGRADED` (испытательный срок 1/3 и 2/3), сохраняясь в `proxy-ok.txt`. Полное выбывание в `DEAD` происходит строго после 3 сбоев подряд.
    - Индикация в `formatted_tag`: `[⭐95]` для стабильных (score >= 90), `[70]` для активных (score < 90), `[⚠️40]` для деградировавших узлов.
    - Ранжирование экспорта в `proxy-ok.txt`: активные узлы по убыванию скора перед деградировавшими узлами, гарантируя быстрые и надежные серверы в начале списка.
    - Автоматическая ленивая нормализация (`_normalize_entry`): полная обратная совместимость со старыми записями `results.json` без ручной миграции.
11. **Оптимизация сетевого конвейера и I/O (High-Throughput Ingestion)**:
    - Мгновенный показ интерактивного меню (0.05с) за счёт подсчёта групп по локальной БД Throne без упреждающего скачивания невыбранных подписок.
    - Параллельная загрузка онлайн-подписок (`fetch_subscriptions_batch`, пул из 8 воркеров) ускоряет сетевой сбор в 3–4 раза (~8.7с вместо 28.8с).
    - Компактная сериализация базы кэша `results.json` (`separators=(',', ':')`): сохранение ускорено в 10 раз (0.5с вместо 4.5с), размер файла уменьшен на 27% (с 19.1 МБ до 13.9 МБ).
12. **Компактный консольный вывод и агрегированная аналитика (Clean Terminal UX)**:
    - Защита консоли от переполнения: по умолчанию выводятся только рабочие серверы (`--table ok`, `AGY-OK` и `DEGRADED`) с ограничением до 20 строк (`--table-limit 20`).
    - Изоляция emoji-флагов: в консоли не используются региональные индикаторы эмодзи, ломающие рендеринг в Windows (CMD/PowerShell). Страны отображаются текстовыми кодами и названиями (`DE (Германия)`).
    - Выделенный модуль расчёта статистики `proxy_probe/stats.py` (`SummaryStats`, SRP/SSOT): агрегирует гео-распределение, задержки (min/median/avg), эффективность подписок (% OK) и категоризацию причин сбоев (L4 TCP, отсев по узлу, геоблок Gemini, таймауты).
    - Обогащенная итоговая панель `print_summary_panel` предоставляет структурированную аналитическую сводку пула без необходимости просмотра всего сырого списка.
