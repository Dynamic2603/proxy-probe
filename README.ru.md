# proxy-probe (`pxp`)

[English](README.md) | **Русский**

---

Инструмент многоступенчатой проверки, отбора и Anti-DPI маршрутизации прокси-серверов под Antigravity (`agy`) и Google Gemini API:
освежает подписки по URL и из локальной БД Throne, отсеивает недоступные сокеты быстрым L4 TCP-предфильтром (Stage 0), поднимает in-memory песочницы движков (`sing-box` / `Xray`) для отбора узлов без региональных ограничений Google (`AGY-OK` против `AGY-BLOCK`, Stage 1), реанимирует заблокированные на уровне ТСПУ/DPI прокси через изолированный локальный релей Zapret2 с фильтрацией WinDivert строго по белому списку IP (Stage 2) и формирует ранжированную подписку (`proxy-ok.txt`) и аналитический отчёт (`report.md`).

---

## Требования

- **Python**: 3.11+ (полная поддержка версий 3.11–3.14).
- **Пакетный менеджер**: [uv](https://docs.astral.sh/uv/) (рекомендуется).

## Запуск

- **Единый интерактивный лаунчер (`run.cmd` / `uv run pxp`)**: выставляет кодировку UTF-8 (`chcp 65001`) и открывает главное TUI-меню в цикле сессии:
  1. Проверка и обновление пула прокси (`Stage 0 TCP -> Stage 1 Direct -> Stage 2 Anti-DPI` с Just-in-Time UAC).
  2. Запуск и остановка постоянного фонового SOCKS5-релея Zapret2 (`127.0.0.1:10850`) для работы спасённых `[zapret]`-узлов в Throne (адаптивный переключатель в меню TUI или команды `uv run pxp --serve [--detach]`, `uv run pxp --stop-relay`, `uv run pxp --status-relay`).
  3. Калибровка стратегий обхода DPI под текущего провайдера (подменю Уровней 2, 3 и 4 или `uv run pxp --calibrate {2|3|4}`).
  4. Обновление каталога 484 стратегий Anti-DPI из upstream (`uv run pxp --update-catalogue`).
  5. Очистка кэша `results.json` от нерабочих записей `DEAD` (`uv run pxp --clear-dead`).
- **Через CLI (`uv`)**:
  ```bash
  uv run pxp [параметры]
  # или полное имя команды:
  uv run proxy-probe [параметры]
  ```

### Примеры параметров
```bash
# Проверить первые 5 серверов
uv run pxp --subset 5

# Запустить в 8 потоков без подтверждения выхода
uv run pxp --jobs 8 --no-pause

# Принудительно перепроверить только упавшие серверы (DEAD), сохранив AGY-OK и AGY-BLOCK
uv run pxp --refresh-dead

# Принудительно перепроверить все серверы в обход кэша
uv run pxp --refresh-cache

# Автоматически опубликовать проверенные прокси в GitHub Secret Gist
uv run pxp --gist <GIST_ID>
```

## Настройка через `.env`

Скопируйте шаблон `.env.example` в `.env` для постоянного сохранения настроек окружения:
```bash
copy .env.example .env
```
Поддерживаемые переменные:
- `PROXY_PROBE_GIST_ID`: ID секретного гиста GitHub для автоматической удалённой доставки подписки.
- `GITHUB_TOKEN`: Personal Access Token GitHub (опционально; по умолчанию токен запрашивается из `gh auth token` утилиты GitHub CLI).
- `AGY_BIN`: путь к исполняемому файлу `agy.exe`.
- `AGY_MODEL`: предпочтительная Flash-модель Gemini (например, `gemini-2.5-flash-lite`).
- `THRONE_DIR`: путь к каталогу данных Throne.
- `PROXY_PROBE_BIN_DIR`: каталог кэша бинарных движков sing-box и Xray.

## Нюансы и ограничения

1. **TOS**: прямых вызовов API с OAuth-токенами Antigravity нет — пробер это сам `agy.exe` с реальным аккаунтом.
2. **Режим TUN (VPN) в Throne искажает прогон**: переменные системного прокси (`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`) автоматически очищаются перед запуском дочерних `sing-box` и `Xray`, однако активный виртуальный сетевой интерфейс (**TUN mode**) в Throne или другом VPN-клиенте перехватывает трафик на сетевом уровне ОС — тогда egress-IP окажется от верхнего туннеля, а не от тестируемого сервера. Для чистых результатов отключайте режим TUN на время прогона.
3. **Одиночный AGY-OK нестабилен**: репутация egress-IP у Gemini меняется со временем.
4. **`agy models` — не проб**: с заблокированного IP модели перечисляются, гео-гейт срабатывает только в print-прогоне.
5. **`agyp`**: вспомогательный враппер `agy` через прокси Throne (порт 2080).
   Внешний файл в одной из папок PATH:
   ```bat
   @echo off
   set HTTP_PROXY=http://127.0.0.1:2080
   set HTTPS_PROXY=http://127.0.0.1:2080
   set ALL_PROXY=http://127.0.0.1:2080
   set NO_PROXY=
   agy.exe %*
   ```
6. **Кэш результатов, скоринг, удержание (Grace Period) и защита от сбоя сети**:
   - Записи в `results.json` индексируются по ключу `Server.cache_key` (`{host}:{port}:{engine}:{sha256(config_identity)[:8]}`), поэтому разные конфигурации и uTLS-отпечатки на одном `host:port` (например, за CDN) хранятся в кэше без коллизий. При экспорте в `proxy-ok.txt` выполняется дедупликация по сервисному эндпоинту (`endpoint_identity`) с выбором сильнейшего профиля по `Server.export_rank`.
   - **Скоринг надежности ($0..100$)**: узлы получают базовые 70 баллов при первом успехе, бонус до +20 за стабильность и штраф за высокую задержку. В канонический тег добавляется бейдж: `[95⭐]` для стабильных (`score >= 90`), `[70]` для обычных и `[40⚠️]` для узлов на испытательном сроке.
   - **Мягкое удержание (Grace Period)**: при транзиентном сетевом сбое (`DEAD`) ранее работавший узел переходит в состояние `DEGRADED` (испытательный срок 1/3 и 2/3) и удерживается в `proxy-ok.txt`. Терминальные сбои (геоблок `AGY-BLOCK`) переводят узел в `DEAD` мгновенно без испытательного срока.
   - **Предохранитель от обрыва локальной сети**: если в прогоне проверялось не менее 5 серверов и 100% из них вернули `DEAD`, штрафные баллы (`consecutive_fails`) для ранее рабочих (`ACTIVE`/`DEGRADED`) узлов в `results.json` не начисляются.
   - **Быстрая очистка (`--clear-dead`)**: удаляет из `results.json` все неактивные записи со статусом `DEAD`, сохраняя `AGY-OK` и `AGY-BLOCK`.
   - TTL по типу: OK — 3 дня, BLOCK — 7 дней, DEAD — 1 день (`--ttl-ok`, `--ttl-blocked`, `--ttl-dead`; 0 = не устаревает; `UNKNOWN` не кешируется).

7. **Защита от исчерпания квоты (`Individual quota reached`) и ускорение запуска**:
   - Автоматически выбирается легчайшая Flash-модель (`detect_best_agy_model`), минимизируя расход квоты (настройка: `--agy-model` или переменная `AGY_MODEL`). Выбор кэшируется в `results.json` на 24 часа, исключая 9-секундную паузу на запрос каталога моделей при регулярных запусках.
   - Параллельные вызовы `agy` ограничены семафором (`--agy-concurrency 2`), исключая всплески rate-limit (HTTP 429).
   - L4 TCP предфильтр (Stage 0) работает в 200 потоков (`--tcp-concurrency 200`), отсекая недоступные TCP-сокеты до запуска движков (UDP-протоколы `hysteria2`/`tuic`/`wireguard` проходят напрямую в Stage 1).
   - Загрузка онлайн-подписок выполняется параллельно пулом воркеров (`fetch_subscriptions_batch`), а база кэша сохраняется в компактном формате (`separators=(',', ':')`), ускоряя I/O в 10 раз.
   - При исчерпании квоты аккаунта автомат `QuotaCircuitBreaker` мгновенно отключает последующие вызовы `agy`: серверы проверяются только на уровне сети (preflight/geo) и отмечаются как `UNKNOWN` (не засоряя кэш).
   - Предстартовая проверка (`--skip-precheck` для отключения) сообщает о статусе квоты до запуска тестирования пула.

8. **Zero-Quota Geo Precheck и веб-проверка (`--check-web`)**:
   - Перед запуском процесса `agy` выполняется предварительный неаутентифицированный HTTP-запрос через туннель к `aistudio.google.com` (150–250мс).
   - Если Google Edge уже на этой стадии возвращает `403 Forbidden` или маркер `User location is not supported`, сервер сразу отбраковывается со статусом `AGY-BLOCK` без расхода квоты и семафора `agy`; узлы, прошедшие предфильтр, далее верифицируются штатным вызовом `agy`.
   - Флаги управления: `--no-geo-precheck`, `--geo-precheck-timeout` (по умолчанию 2.5с).
   - Опция `--check-web`: проверяет доступность `gemini.google.com` и выявляет интерактивный челлендж Google CAPTCHA (`google.com/sorry`). Наличие капчи не отменяет работоспособность API (`AGY-OK`), но добавляет информационный маркер `[captcha]` в тег сервера и отчёт.

9. **Изолированный обход ТСПУ/DPI (Stage 2 Zapret2 Relay и мультипровайдерный рейтинг)**:
   - Для серверов, чей TCP-порт открыт (Stage 0), но соединение с которыми сбрасывается на уровне TLS/DPI в Stage 1, автоматически запускается второй этап (`--antidpi`, отключение: `--no-antidpi`).
   - Перехват пакетов драйвером `WinDivert` (`winws2.exe`) ограничивается строго белым списком IP проверяемой пачки (до 150 IP за итерацию) и не затрагивает остальной трафик ОС.
   - Спасённые серверы помечаются бейджем `[zapret]` и экспортируются в `proxy-ok.txt` с маршрутизацией `dialerProxy: "zapret-relay"` через локальный SOCKS5-релей (`127.0.0.1:10850`, запускаемый для постоянной работы через пункт 2 меню `run.cmd` или `uv run pxp --serve`). Если в последующем запуске такой сервер проходит Stage 1 напрямую, привязка к Zapret в кэше автоматически снимается.
   - Рейтинги стратегий (`data/antidpi_ratings.json`) изолированы по ASN входящего интернет-провайдера (`IspIdentity`, переопределение: `--isp`); при невозможности определить провайдера действует строгий Fail-Fast без подстановки чужих профилей.

## Подключение `proxy-ok.txt` как подписки в Throne

### Вариант А: Локальная подписка (на том же ПК)
Вместо разового ручного импорта файл `proxy-ok.txt` можно подключить как постоянную локальную подписку (без необходимости поднимать локальный веб-сервер):

1. В клиенте Throne: **Группы** (`Groups`) -> **Добавить группу** (`Add Group`).
2. Заполнить параметры:
   - **Имя**: `PROXY-OK`
   - **Тип**: `Подписка`
   - **URL подписки**: `file:///C:/path/to/proxy-probe/proxy-ok.txt` *(укажите абсолютный путь к файлу в вашей системе; обязательно 3 прямых слэша перед буквой диска на Windows)*.
3. По кнопке «Обновить» Throne считывает локальный файл через файловый движок Qt (`QNetworkReplyFileImpl`) и автоматически синхронизирует профили (удаляя выбывшие и добавляя новые).

### Вариант Б: Удалённая приватная доставка через GitHub Secret Gist (Zero-Server Remote Sync)
Для автоматической доставки пула на мобильные устройства, ноутбуки или удалённые ПК без развёртывания веб-серверов:

1. **Создайте Secret Gist (один раз)**:
   ```bash
   gh gist create proxy-ok.txt --desc "Throne Proxy Pool"
   ```
   *(GitHub CLI создаст секретную заметку с 128-битным хэшем, например `5b0e0062eb8e9654adad7bb1d81cc75f`).*
2. **Настройте автообновление**:
   Укажите `PROXY_PROBE_GIST_ID=<GIST_ID>` в `.env` (или передавайте флаг `--gist <GIST_ID>`).
   Каждый запуск `pxp` будет автоматически актуализировать `proxy-ok.txt` в гисте.
3. **В Throne на любом устройстве**:
   - **URL подписки**: `https://gist.githubusercontent.com/<username>/<gist_id>/raw/proxy-ok.txt`
   - **Интервал обновления**: например, 30 или 60 минут.
   - GitHub Fastly CDN кэширует данный динамический пермалинк всего на 5 минут (`max-age=300`), гарантируя регулярное обновление подписки на всех устройствах.
