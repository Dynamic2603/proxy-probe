# proxy-probe (`pxp`)

[English](README.md) | **Русский**

---

Универсальный инструмент проверки, отбора и маршрутизации прокси-серверов:
освежает подписки по URL или из БД клиентов, поднимает изолированные песочницы движков (`sing-box` / `Xray`), валидирует пригодность узлов под целевые утилиты и сервисы (Antigravity `agy` / Gemini API) в обход гео-блокировок (`User location is not supported`), классифицирует серверы (`AGY-OK` / `AGY-BLOCK` / `DEAD`) и формирует файлы подписок (`proxy-ok.txt`) и отчёты (`report.md`).

---

## Требования

- **Python**: 3.11+ (полная поддержка версий 3.11–3.14).
- **Пакетный менеджер**: [uv](https://docs.astral.sh/uv/) (рекомендуется).


## Запуск

- **Через командный файл**: `run.cmd`. Автоматически выставляет кодировку UTF-8 (`chcp 65001`), запускает утилиту через `uv run pxp` и ожидает нажатия Enter перед закрытием окна.
- **Через CLI (`uv`)**:
  ```bash
  uv run pxp [параметры]
  # или полное имя команды:
  uv run proxy-probe [параметры]
  ```

### Примеры параметров
```bash
# Проверить первые 5 серверов
uv run pxp --subset 5

# Запустить в 8 потоков без подтверждения выхода
uv run pxp --jobs 8 --no-pause

# Принудительно перепроверить серверы в обход кэша
uv run pxp --refresh-cache
```

## Нюансы и ограничения

1. **TOS**: прямых вызовов API с OAuth-токенами Antigravity нет — пробер это сам `agy.exe` с реальным аккаунтом.
2. **GUI Throne искажает прогон**: одновременный активный туннель/прокси/системное прокси в Throne → egress у движка может быть верхнего туннеля, а не тестируемого сервера. Для чистых результатов прогон делать при выключенном туннеле.
3. **Одиночный AGY-OK нестабилен**: репутация egress-IP у Gemini меняется со временем.
4. **`agy models` — не проб**: с заблокированного IP модели перечисляются, гео-гейт срабатывает только в print-прогоне.
5. **`agyp`**: вспомогательный враппер `agy` через прокси Throne (порт 2080).
   Внешний файл в одной из папок PATH:
   ```bat
   @echo off
   set HTTP_PROXY=http://127.0.0.1:2080
   set HTTPS_PROXY=http://127.0.0.1:2080
   set ALL_PROXY=http://127.0.0.1:2080
   set NO_PROXY=
   agy.exe %*
   ```
6. **Кэш результатов**: результаты `AGY-OK` / `AGY-BLOCK` / `DEAD` кешируются в `results.json` рядом со скриптом (ключ — сервер `host:port`) и в следующих прогонах не перепроверяются (не запускаются движок/agy).
   TTL по типу: OK — 3 дня, BLOCK — 7 дней, DEAD — 1 день (`--ttl-ok`, `--ttl-blocked`, `--ttl-dead`; 0 = не устаревает; `UNKNOWN` не кешируется).
   При коллизии одного `host:port` (несколько конфигов) приоритет результата: `BLOCK` > `AGY-OK` > `DEAD` — битый второй конфиг не понижает BLOCK до DEAD.
   Кэшированные `AGY-OK` попадают в `proxy-ok.txt` наравне со свежими.

## Подключение `proxy-ok.txt` как подписки в Throne

Вместо разового ручного импорта файл `proxy-ok.txt` можно подключить как постоянную локальную подписку (без необходимости поднимать локальный веб-сервер):

1. В клиенте Throne: **Группы** (`Groups`) -> **Добавить группу** (`Add Group`).
2. Заполнить параметры:
   - **Имя**: `PROXY-OK`
   - **Тип**: `Подписка`
   - **URL подписки**: `file:///C:/path/to/proxy-probe/proxy-ok.txt` *(укажите абсолютный путь к файлу в вашей системе; обязательно 3 прямых слэша перед буквой диска на Windows)*.
3. По кнопке «Обновить» Throne считывает локальный файл через файловый движок Qt (`QNetworkReplyFileImpl`) и автоматически синхронизирует профили (удаляя выбывшие и добавляя новые).
